# 이전 프로젝트의 파일럿 측정

agent-harness 는 한 Spring Boot 프로젝트(Java 21, 설계 문서 21개)에 붙어 있던 Claude Code 전용 하네스를 일반화한 것이다.
그 하네스에서 16개 실험을 돌렸다. 여기서는 결론과 한계를 **같은 무게로** 옮긴다.

## 결론 (방향성, 법칙 아님)

하네스를 두 절반으로 나눴다. **미리 알려주기**(세션 시작·편집 직전에 설계 문서 주입)와 **사후에 잡기**(편집 직후 적대자·결정론 게이트·런타임 확인)다.

| 무엇을 쟀나 | 결과 | 실험 |
|---|---|---|
| 설계 문서 주입이 규칙 준수를 올리나 | 차이 거의 0. 유능한 모델은 기존 코드와 문서에서 알아서 찾아 읽었다 | COMPLIANCE, BOUNDARY, DRIFT(생성 쪽) |
| 생성 규칙을 강하게 걸면 품질이 오르나 | 과제 난이도에 따라 부호가 바뀜. 단순 과제 −2.5(과설계), 복잡 과제 +7.5 | GENQUALITY |
| 사후 적대자가 실제 버그를 잡나 | 판별 쌍 8개에서 recall 4/4, 하드 오탐 0. 약한 모델이 낸 트랜잭션 자기호출 버그를 힌트 없이 적발 | ADVERSARY, DRIFT(검증 쪽) |
| 검증자에게 도구·렌즈를 더 주면 정확도가 오르나 | 추론으로 풀리는 대상에서는 0. 값은 감사 가능성 | H1·H2·H3·H4·H4b·v3·H5·H8·H11 |
| 런타임 상태가 정답을 가르면 | 도구로 확인한 쪽만 정답 (2/2 vs 2/4) | v-next |

agent-harness 에 반영한 것:
- 주입 기계(설계 문서 라우팅, 문서 발췌 검색)는 옮기지 않았다. 세션 주입은 추론할 수 없는 상태(원장·진행 상황)만 한다.
- 결정론 게이트와 적대자를 옮겼다.
- 생성 규칙은 강제하지 않고 경고로 둔다. 적대자 프로토콜이 과설계도 위반으로 본다.
- 다수결 패널은 넣지 않았다. 같은 모델의 렌즈를 늘려도 오차가 상관돼 있어 이득이 없었다.

## 한계 (전부)

- **표본이 작다.** 대부분 n=1~8. p값·신뢰구간·반복이 없다.
- **"차이 0" 은 "같다" 가 아니다.** 대개 양쪽 다 천장에 붙어서 생긴 검정력 부족이다.
- **재현이 안 되는 것이 있다.** v-next 와 GENQUALITY 는 원시 산출물이 남아 있지 않다.
- **자기 채점이다.** 실험 설계·실행·채점·해석을 같은 계열의 에이전트가 했다.
- **표본 오염.** ADVERSARY 의 "깨끗한" 샘플 하나가 기존 코드 복사본이라 정밀도의 분모는 사실상 3이다.
- **동어반복 위험.** v-next 는 정답 정보를 한쪽에서만 뺀 설계라, 효과 크기로 읽으면 안 된다.
- **안 잰 것.** 비용, 긴 세션의 드리프트, 적대자의 대규모 recall·오탐률, 다른 스택.

## 외부 근거와 비교하면

이전 측정 자체는 약하지만, 그 방향(외부 검증 쪽에 값이 있다)은 독립된 근거들과 같은 쪽을 가리킨다.
- 외부 피드백 없는 자기 수정은 악화된다 (Huang ICLR'24, CRITIC ICLR'24).
- 하네스만 바꾼 검증 루프로 Terminal-Bench 52.8→66.5% (LangChain 2026-02).
- 브라우저 테스트 도구가 장기 실행 에이전트의 성능을 크게 올렸다 (Anthropic 2025-11).
- 도구를 80% 줄였더니 성공률이 올랐다 (Vercel, Marmelab 2026-09 에서 인용). 더하는 쪽이 늘 좋은 것은 아니다.
